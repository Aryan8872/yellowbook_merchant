# PLAN 03-02: Branch Creation and Editing with Operating Hours

## Objective

Implement the branch creation and editing functionality with a comprehensive form that includes contact details, operating hours schedule builder, and status management.

## Context

This plan builds on Plan 03-01's data layer and listing page. It adds the ability to create new branches and edit existing ones through a modal-based form. The operating hours builder is a key feature that requires a custom UI component.

## Tasks

### Task 1: Create Operating Hours Builder Component

**Files to create:**
- `components/branches/OperatingHoursBuilder.tsx` - operating hours schedule UI

**Implementation:**
1. Create component with 7 day rows (Monday-Sunday)
2. Each row includes:
   - Day label
   - "Closed" toggle (checkbox)
   - Open time picker (when not closed)
   - Close time picker (when not closed)
3. Add "Copy to all days" button:
   - Opens a modal to select which day's schedule to copy
   - Applies the selected schedule to all other days
4. Time picker using Base UI TimeField or similar
5. Time format: HH:MM (24-hour)
6. Validation: close time must be after open time
7. Export value as object: `{ monday: { open: "09:00", close: "22:00" }, ... }`
8. Import value from existing branch data (for edit mode)

**Success criteria:**
- 7 day rows display correctly
- Closed toggle hides/shows time pickers
- Time pickers work with HH:MM format
- Copy to all days function works
- Validation prevents invalid time ranges
- Component exports correct data structure
- Component accepts initial data for edit mode

---

### Task 2: Create Branch Form Component

**Files to create:**
- `components/branches/BranchForm.tsx` - branch creation/editing form

**Implementation:**
1. Create form with fields:
   - Name (text input, required)
   - Address (text input, required)
   - City (text input, required)
   - Phone (text input, required, Nepal format validation)
   - Status (toggle switch, default: active)
   - Operating Hours (OperatingHoursBuilder component)
   - Latitude (number input, optional, range: -90 to 90)
   - Longitude (number input, optional, range: -180 to 180)
2. Use react-hook-form for form management
3. Integrate Zod schemas from Plan 03-01 for validation
4. Add loading state during submission
5. Add error display for validation errors
6. Support both create and edit modes (via props)
7. Pre-fill form with branch data in edit mode
8. Add cancel button to close modal

**Success criteria:**
- Form renders with all fields
- Validation works for all required fields
- Phone number validates Nepal format
- Coordinate ranges enforced
- Loading state shows during submission
- Errors display inline
- Edit mode pre-fills with existing data
- Cancel button closes modal

### Task 3: Create Branch Modal Component

**Files to create:**
- `components/branches/BranchModal.tsx` - modal wrapper for branch form

**Implementation:**
1. Create modal using Base UI Modal
2. Modal title: "Add Branch" (create) or "Edit Branch" (edit)
3. Embed BranchForm component
4. Handle open/close state
5. Pass mode (create/edit) and branch data to form
6. Handle form submission:
   - Call branch store action (createBranch or updateBranch)
   - Close modal on success
   - Show success toast notification
   - Refresh branch list on success
7. Handle errors:
   - Display error message
   - Keep modal open on error
8. Add confirmation dialog for delete action (in edit mode)

**Success criteria:**
- Modal opens/closes correctly
- Title changes based on mode
- Form submission calls correct API
- Modal closes on success
- Success toast displays
- Branch list refreshes after create/update
- Error message displays on failure
- Delete confirmation dialog works
