# PLAN 03-01: Branch API Client, Data Models, and Listing Table

## Objective

Build the foundation for branch management by creating the API client layer, TypeScript data models, and the branch listing DataTable page with search and pagination.

## Context

This plan establishes the data layer and the primary UI for viewing branches. It depends on Phase 1's API client infrastructure and Phase 2's merchant context. The branch listing page will be the entry point for all branch operations.

## Tasks

### Task 1: Create Branch Data Models and Validation Schemas

**Files to create:**
- `lib/types/branch.ts` - TypeScript interfaces and types
- `lib/schemas/branch.ts` - Zod validation schemas

**Implementation:**
1. Define TypeScript interfaces:
   - `Branch` - full branch entity
   - `CreateBranchDto` - create request payload
   - `UpdateBranchDto` - update request payload
   - `OperatingHours` - operating hours type (day-of-week object)
2. Create Zod schemas matching API DTOs
3. Add coordinate validation (lat: -90 to 90, lng: -180 to 180)
4. Add phone number validation (Nepal format: +977 or 9-10 digits)
5. Export types and schemas for reuse

**Success criteria:**
- Types match API response/request schemas exactly
- Zod schemas validate all required fields
- Coordinate ranges enforced
- TypeScript compilation passes

---

### Task 2: Create Branch API Client Functions

**Files to create:**
- `lib/api/branches.ts` - branch-specific API functions
- `lib/api/mocks/branches.ts` - mock data and fallback

**Implementation:**
1. Create API functions using standardized envelope wrapper:
   - `getBranches(merchantId: string, params?: { page?: number, limit?: number, search?: string })`
   - `createBranch(merchantId: string, data: CreateBranchDto)`
   - `updateBranch(branchId: string, data: UpdateBranchDto)`
   - `deleteBranch(branchId: string)`
2. Use `apiClient` from `lib/api/client.ts`
3. Handle pagination metadata from response envelope
4. Create mock data with 10-15 sample branches across different cities
5. Implement mock fallback function that returns mock data on API failure
6. Add TypeScript types for all function signatures

**Success criteria:**
- All API functions follow envelope pattern
- Mock data includes diverse cities and statuses
- Fallback activates on 404/500/offline errors
- Functions return typed responses

---

### Task 3: Create Branch Zustand Store

**Files to create:**
- `lib/stores/branchStore.ts` - branch state management

**Implementation:**
1. Create Zustand store with:
   - State: `branches: Branch[]`, `loading: boolean`, `error: string | null`, `pagination: PaginationMeta`
   - Actions: `fetchBranches()`, `createBranch()`, `updateBranch()`, `deleteBranch()`, `clearError()`
2. Integrate with API client functions
3. Add loading states for async operations
4. Add error handling with user-friendly messages
5. Persist branches to localStorage for offline resilience
6. Follow pattern from Phase 2's `useProfileStore`

**Success criteria:**
- Store manages branch list state
- Loading states update correctly
- Errors are captured and exposed
- LocalStorage persistence works
- TypeScript types are correct

### Task 4: Create Branch Listing Page with DataTable

**Files to create:**
- `app/(merchant)/merchant/branches/page.tsx` - branch list page
- `components/branches/BranchTable.tsx` - DataTable component

**Implementation:**
1. Create branch list page:
   - Use branch store to fetch branches on mount
   - Display loading spinner while fetching
   - Show error message if fetch fails
   - Pass branches to BranchTable component
   - Add "Add Branch" button (disabled for now, enabled in Plan 03-02)
2. Create BranchTable component:
   - Use existing DataTable component from Phase 1
   - Columns: Name, City, Phone, Status (badge), Actions (edit/delete buttons - disabled for now)
   - Implement server-side pagination via store
   - Add search input that filters by name or city
   - Status badge: green for active, gray for inactive
   - Empty state when no branches exist
3. Add responsive design for mobile
4. Add skeleton loading state

**Success criteria:**
- Branch list displays on page load
- DataTable renders with correct columns
- Pagination works (page 1, 2, etc.)
- Search filters branches by name or city
- Status badges display correctly
- Empty state shows helpful message
- Mobile responsive
