# Plan 04-03: Branch Editing & Geofence Configuration

## Objective
Create a branch edit form (reusing the creation form), implement geofence radius configuration, add branch status toggle, create branch delete confirmation, and connect to updateBranch/deleteBranch APIs.

## Success Criteria
1. Branch edit form pre-fills with existing branch data
2. Geofence radius can be configured with validation
3. Branch status can be toggled with confirmation
4. Branch deletion requires confirmation dialog
5. Edit form calls updateBranch API
6. Delete action calls deleteBranch API
7. Success/error handling with toast notifications
8. Branch list refreshes after updates

## Tasks

### Task 1: Create Branch Edit Page
**File**: `app/(merchant)/merchant/branches/[id]/page.tsx`

**Description**: Create a dedicated page for editing a branch with all branch details.

**Implementation Details**:
- Import branch store and auth store
- Get `branchId` from URL params
- Get `merchantId` from auth store
- Fetch branch data on mount using `useEffect`
- Show loading state while fetching
- Show error state if fetch fails
- Render branch edit form (reuse BranchForm component)
- Pre-fill form with branch data
- Add page title: "Edit Branch"
- Add breadcrumb navigation
- Add "Back to Branches" button
- Handle form submission
- Call branch store `updateBranch` action
- Show success/error toasts
- Redirect to branch list on success

**Acceptance Criteria**:
- Page loads and fetches branch data
- Form pre-fills with existing data
- Submit button calls update API
- Success toast shows on update
- Error toast shows on failure
- Redirects to branch list on success
- Loading state shows while fetching
- Error state shows retry button

### Task 2: Update Branch Form for Edit Mode
**File**: Update `components/merchant/branch-form.tsx`

**Description**: Modify the branch form to support both creation and edit modes.

**Implementation Details**:
- Add prop: `mode: 'create' | 'edit'`
- Add prop: `initialData?: Branch` (for edit mode)
- Add prop: `branchId?: string` (for edit mode)
- If `mode === 'edit'` and `initialData` provided:
  - Pre-fill form with initialData
  - Change submit button text to "Update Branch"
  - Call `updateBranch` instead of `createBranch`
- If `mode === 'create'`:
  - Keep existing behavior
  - Call `createBranch`
- Add validation for required fields in edit mode (some may be optional)
- Handle partial updates (only changed fields)

**Acceptance Criteria**:
- Form works in both create and edit modes
- Edit mode pre-fills with data
- Submit button text changes based on mode
- Correct API is called based on mode
- Validation works in both modes

### Task 3: Add Geofence Radius Configuration
**File**: Update `components/merchant/branch-form.tsx` or create `components/merchant/geofence-config.tsx`

**Description**: Add geofence radius input with validation and visual feedback.

**Implementation Details**:
- Add geofence radius input field
- Add suffix "meters" to input
- Add validation: min 10m, max 5000m
- Add helper text explaining geofence
- Add preset buttons: 100m, 500m, 1000m, 2000m
- Show estimated coverage area (π × r²)
- Optional: Add simple circle visualization (CSS-based)
- Make field optional (default to backend default if not set)

**Acceptance Criteria**:
- Input accepts radius in meters
- Validation enforces min/max limits
- Preset buttons set common values
- Helper text explains geofence
- Estimated area displays
- Field is optional
