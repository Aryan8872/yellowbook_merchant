# Plan 04-01: Branch API Client & Listing Table

## Objective
Create a Zustand store for branch state management, build a DataTable component with pagination and search, and implement the branch listing page with status indicators and action buttons.

## Success Criteria
1. Branch Zustand store manages state (branches, loading, error, pagination)
2. DataTable component supports pagination, search, and filtering
3. Branch listing page displays all branches with status badges
4. Search and filter functionality works correctly
5. Action buttons (edit, delete, toggle status) are displayed
6. Loading and error states are handled gracefully

## Tasks

### Task 1: Create Branch Zustand Store
**File**: `lib/merchant/stores/branches-store.ts`

**Description**: Create a Zustand store with persist middleware for managing branch state.

**Implementation Details**:
- Import existing branch types from `lib/types/branch.ts`
- Import branch API functions from `lib/api/branches.ts`
- Define state interface:
  - `branches: Branch[]`
  - `total: number`
  - `page: number`
  - `limit: number`
  - `totalPages: number`
  - `loading: boolean`
  - `error: string | null`
  - `filters: BranchListParams`
- Implement actions:
  - `fetchBranches(merchantId, params)` - Fetch branches with pagination
  - `fetchBranch(merchantId, branchId)` - Fetch single branch
  - `createBranch(merchantId, data)` - Create new branch
  - `updateBranch(branchId, data)` - Update branch
  - `deleteBranch(branchId)` - Delete branch
  - `setFilters(filters)` - Update search/filter params
  - `clearError()` - Clear error state
- Use persist middleware with name `offernepal-merchant-branches`
- Partialize state to persist only filters

**Acceptance Criteria**:
- Store compiles without TypeScript errors
- Fetch branches action calls API correctly
- Loading and error states are managed
- Filters are persisted across sessions

### Task 2: Create DataTable Component
**File**: `components/ui/data-table.tsx` (or `components/merchant/data-table.tsx`)

**Description**: Create a reusable DataTable component extending shadcn Table with pagination, search, and filtering.

**Implementation Details**:
- Extend shadcn Table component
- Add props:
  - `data: T[]` - Table data
  - `columns: ColumnDef<T>[]` - Column definitions
  - `searchable?: boolean` - Enable search input
  - `filterable?: boolean` - Enable filter dropdown
  - `pagination?: boolean` - Enable pagination
  - `pageSize?: number` - Items per page
- Implement search input with debounce
- Implement pagination controls (prev, next, page numbers)
- Implement filter dropdown (status, city, etc.)
- Add loading skeleton
- Add empty state message
- Use TanStack Table core for advanced features if needed

**Acceptance Criteria**:
- Component renders table with data
- Search filters data correctly
- Pagination works (page 1, 2, 3, etc.)
- Filters apply correctly
- Loading state shows skeleton
- Empty state shows message

## Risks

1. **DataTable Complexity**: Building a full-featured DataTable may be complex. Mitigation: Start with basic table, add features incrementally.
2. **Performance**: Large branch lists may slow down. Mitigation: Implement server-side pagination, virtualization.
3. **Filter Logic**: Complex filter combinations may be tricky. Mitigation: Keep filters simple, test thoroughly.
