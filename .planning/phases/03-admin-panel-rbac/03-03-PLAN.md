# Plan 03-03: Admin API Integration

**Status:** Pending
**Type:** Backend Integration
**Priority:** High
**Effort:** 8 hours

## Objective

Connect admin-specific API endpoints through Next.js API route proxies, implement admin state management with Zustand stores, and build functional user management and merchant management UIs with real data.

## Success Criteria

1. Admin API service layer created with typed functions
2. Next.js API route proxies implemented for all admin endpoints
3. Admin Zustand stores created for user and merchant management
4. User management UI connected to API with full CRUD functionality
5. Merchant management UI connected to API with approval/rejection functionality
6. Analytics dashboard connected to API with real metrics
7. Error handling and loading states implemented throughout
8. API contracts match backend DTOs to prevent 400 Bad Request errors

## Tasks

### Task 1: Create Admin API Service Layer

**File:** `lib/api/admin/users-api.ts`, `lib/api/admin/merchants-api.ts`, `lib/api/admin/analytics-api.ts`

**Description:** Create typed API service functions for admin endpoints.

**Steps:**
1. Create `lib/api/admin/users-api.ts`:
   - `getUsers(params)` - List users with pagination/filtering
   - `getUser(id)` - Get user details
   - `updateUser(id, data)` - Update user
   - `deactivateUser(id)` - Deactivate user
   - `activateUser(id)` - Activate user
2. Create `lib/api/admin/merchants-api.ts`:
   - `getMerchants(params)` - List merchants with pagination/filtering
   - `getMerchant(id)` - Get merchant details
   - `updateMerchant(id, data)` - Update merchant
   - `approveMerchant(id)` - Approve merchant
   - `rejectMerchant(id, reason)` - Reject merchant
   - `suspendMerchant(id)` - Suspend merchant
3. Create `lib/api/admin/analytics-api.ts`:
   - `getOverview()` - Platform overview stats
   - `getUserMetrics()` - User growth metrics
   - `getMerchantMetrics()` - Merchant metrics
   - `getRedemptionMetrics()` - Redemption metrics
4. Use existing `apiClient` from `lib/api/client.ts`
5. Add proper TypeScript types matching backend DTOs
6. Add error handling with ApiError types

**Acceptance Criteria:**
- All API functions are type-safe
- Functions match backend endpoint signatures
- Error handling is consistent
- Functions are exported from `lib/api/admin/index.ts`

### Task 2: Create Next.js API Route Proxies

**Files:** `app/api/admin/users/route.ts`, `app/api/admin/users/[id]/route.ts`, etc.

**Description:** Create Next.js API route proxies to handle authentication and forward requests to backend.

**Steps:**
1. Create `app/api/admin/users/route.ts`:
   - GET: Proxy to `/api/v1/admin/users` with auth token
   - POST: Proxy to `/api/v1/admin/users` (if backend supports)
2. Create `app/api/admin/users/[id]/route.ts`:
   - GET: Proxy to `/api/v1/admin/users/:id`
   - PATCH: Proxy to `/api/v1/admin/users/:id`
   - DELETE: Proxy to `/api/v1/admin/users/:id`
3. Create `app/api/admin/users/[id]/activate/route.ts`:
   - POST: Proxy to `/api/v1/admin/users/:id/activate`
4. Create `app/api/admin/merchants/route.ts`:
   - GET: Proxy to `/api/v1/admin/merchants`
5. Create `app/api/admin/merchants/[id]/route.ts`:
   - GET: Proxy to `/api/v1/admin/merchants/:id`
   - PATCH: Proxy to `/api/v1/admin/merchants/:id`
6. Create `app/api/admin/merchants/[id]/approve/route.ts`:
   - POST: Proxy to `/api/v1/admin/merchants/:id/approve`
7. Create `app/api/admin/merchants/[id]/reject/route.ts`:
   - POST: Proxy to `/api/v1/admin/merchants/:id/reject`
8. Create `app/api/admin/analytics/route.ts`:
   - GET: Proxy to `/api/v1/admin/analytics/overview`
9. Add authentication check in all routes (validate accessToken cookie)
10. Add role validation (ADMIN only)
11. Add error handling and logging

**Acceptance Criteria:**
- All proxies correctly forward requests to backend
- Authentication is validated on every request
- Role validation enforces ADMIN-only access
- Error responses match backend format
- CORS headers are properly set

### Task 3: Create Admin Zustand Stores

**Files:** `lib/admin/stores/users-store.ts`, `lib/admin/stores/merchants-store.ts`, `lib/admin/stores/analytics-store.ts`

**Description:** Create Zustand stores for admin state management.

**Steps:**
1. Create `lib/admin/stores/users-store.ts`:
   - State: users list, loading, error, pagination, filters
   - Actions: fetchUsers, updateUser, deactivateUser, activateUser, setFilters
   - Persist user list to localStorage (optional)
2. Create `lib/admin/stores/merchants-store.ts`:
   - State: merchants list, loading, error, pagination, filters
   - Actions: fetchMerchants, approveMerchant, rejectMerchant, suspendMerchant, setFilters
3. Create `lib/admin/stores/analytics-store.ts`:
   - State: overview stats, loading, error
   - Actions: fetchOverview, fetchUserMetrics, fetchMerchantMetrics
4. Use persist middleware for relevant stores
5. Add TypeScript types for all state
6. Add optimistic updates for better UX

**Acceptance Criteria:**
- Stores are type-safe
- Actions handle loading and error states
- Stores integrate with API service layer
- State is persisted where appropriate
