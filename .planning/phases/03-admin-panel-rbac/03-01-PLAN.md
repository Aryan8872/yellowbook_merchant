# Plan 03-01: RBAC Middleware Implementation

**Status:** Pending
**Type:** Infrastructure
**Priority:** High
**Effort:** 4 hours

## Objective

Implement role-based access control (RBAC) middleware to enforce role-based access to protected routes, ensuring ADMIN, MERCHANT_ADMIN, and MERCHANT_STAFF users can only access routes appropriate to their role.

## Success Criteria

1. Permission constants and role matrix defined in centralized location
2. Middleware.ts enhanced with JWT decoding and role validation
3. Role-based route guards implemented for /admin/* and /merchant/* routes
4. Unauthorized users redirected to appropriate login pages based on role
5. Unit tests for permission utility functions
6. Integration tests for middleware role enforcement

## Tasks

### Task 1: Define Permission Constants and Role Matrix

**File:** `lib/auth/permissions.ts`

**Description:** Create centralized permission definitions and role-to-permission mapping.

**Steps:**
1. Create `lib/auth/permissions.ts` file
2. Define `UserRole` enum (ADMIN, MERCHANT_ADMIN, MERCHANT_STAFF, USER)
3. Define `PERMISSIONS` constant with all system permissions
4. Define `ROLE_PERMISSIONS` mapping roles to permission arrays
5. Export `hasPermission(role, permission)` utility function
6. Export `getRequiredPermissions(route)` function for route-based permission lookup

**Acceptance Criteria:**
- All permissions are documented with descriptions
- Role matrix is complete and accurate
- Utility functions are type-safe
- File is exported from `lib/auth/index.ts`

### Task 2: Implement Permission Utility Functions

**File:** `lib/auth/permissions.ts` (extend)

**Description:** Add helper functions for permission checking and JWT decoding.

**Steps:**
1. Implement `decodeJWT(token)` function to decode JWT payload
2. Implement `getUserRole(token)` function to extract role from JWT
3. Implement `validateToken(token)` function to check token expiration
4. Implement `hasAllPermissions(role, permissions)` function
5. Implement `hasAnyPermission(role, permissions)` function
6. Add error handling for invalid/expired tokens

**Acceptance Criteria:**
- Functions handle edge cases (invalid token, missing role claim)
- Token expiration is checked
- Functions are unit tested
- Error messages are clear

### Task 3: Enhance Middleware with Role Validation

**File:** `middleware.ts`

**Description:** Update existing middleware to decode JWT and validate user role against route requirements.

**Steps:**
1. Import permission utilities from `lib/auth/permissions.ts`
2. Define route-to-role mapping (e.g., `/admin/*` requires ADMIN, `/merchant/*` requires MERCHANT_ADMIN or MERCHANT_STAFF)
3. Decode JWT from accessToken cookie
4. Extract user role from JWT payload
5. Validate role against route requirements
6. Redirect unauthorized users to appropriate login:
   - ADMIN users trying to access merchant routes → /admin/dashboard
   - MERCHANT users trying to access admin routes → /merchant/dashboard
   - Unauthenticated users → /merchant/auth/login or /admin/auth/login
7. Handle token expiration by redirecting to refresh endpoint

**Acceptance Criteria:**
- Middleware correctly decodes JWT
- Role validation works for all protected routes
- Redirects are appropriate to user role
- Token expiration is handled gracefully
- Public routes are not affected

### Task 4: Add Role-Based Route Guards

**File:** `lib/auth/route-guards.ts` (new)

**Description:** Create reusable route guard components for server-side and client-side protection.

**Steps:**
1. Create `lib/auth/route-guards.ts` file
2. Implement `withRoleGuard(component, allowedRoles)` HOC
3. Implement `useRoleGuard(allowedRoles)` hook for client-side checks
4. Implement `requireRole(allowedRoles)` function for server components
5. Add role check to existing auth-store for client-side state
6. Create role-aware redirect utility

**Acceptance Criteria:**
- Guards work for both server and client components
- Unauthorized access triggers appropriate redirect
- Guards are reusable across the application
- Type-safe with TypeScript

### Task 5: Test Unauthorized Access Scenarios

**Files:** Unit tests, integration tests

**Description:** Write comprehensive tests for RBAC implementation.

**Steps:**
1. Write unit tests for permission utility functions
2. Write unit tests for JWT decoding functions
3. Write integration tests for middleware role validation
4. Test scenarios:
   - ADMIN accessing admin routes (should succeed)
   - MERCHANT accessing admin routes (should redirect)
   - MERCHANT accessing merchant routes (should succeed)
   - Unauthenticated accessing protected routes (should redirect to login)
   - Expired token handling
   - Invalid token handling
5. Add test coverage report

**Acceptance Criteria:**
- All permission functions have unit tests
- Middleware has integration tests
- Test coverage > 80% for RBAC code
- All edge cases are tested

## Dependencies

## Risks

- **Risk:** JWT decoding in middleware may impact performance
  **Mitigation:** Cache decoded claims, use efficient JWT library

- **Risk:** Role changes not reflected until token refresh
  **Mitigation:** Implement short token expiration, document limitation

- **Risk:** Breaking existing merchant routes
  **Mitigation:** Thorough testing, gradual rollout
