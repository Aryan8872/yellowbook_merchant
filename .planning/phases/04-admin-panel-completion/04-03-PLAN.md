# Plan 04-03: Complete Admin UI Components

## Objective
Create the admin user edit dialog component and the admin merchant details page to complete the admin panel UI.

## Success Criteria
1. User edit dialog component is created with form validation
2. User edit dialog integrates with user store
3. Merchant details page is created with merchant information
4. Merchant details page includes approval/rejection/suspension actions
5. Both components use shadcn components and follow design system
6. Both components have proper error handling and loading states

## Tasks

**Description**: Install Sonner for toast notifications.

**Implementation Details**:
- Run `npx shadcn@latest add sonner`
- Add Toaster component to root layout
- Verify installation

**Acceptance Criteria**:
- Sonner is installed
- Toaster is added to layout

### Task 2: Create User Edit Dialog Component
**File**: `lib/admin/components/user-edit-dialog.tsx`

**Description**: Create a dialog component for editing user details.

**Implementation Details**:
- Import shadcn Dialog components
- Import React Hook Form and Zod
- Import user types from `lib/api/admin/users-api.ts`
- Import user store from `lib/admin/stores/users-store.ts`
- Define Zod schema for user update:
  - name: string, min 2, max 100
  - role: enum (ADMIN, MERCHANT_ADMIN, MERCHANT_STAFF, USER)
  - phone: string, optional, phone format
  - avatarUrl: string, optional, URL format
  - isActive: boolean
  - merchantId: string, optional (for merchant roles)
- Create form with fields:
  - name (Input)
  - role (Select)
  - phone (Input)
  - avatarUrl (Input)
  - isActive (Switch)
  - merchantId (Input, conditional on role)
- Add validation errors display
- Add submit button
- Add cancel button
- Handle form submission
- Call user store `updateUser` action
- Show success/error toasts
- Close dialog on success
- Add loading state during submission

**Acceptance Criteria**:
- Dialog opens/closes correctly
- Form renders all fields
- Validation works
- Submit calls API
- Success toast shows
- Error toast shows
- Dialog closes on success
- Loading state shows

### Task 4: Create Merchant Details Page

**Implementation Details**:

- Call merchant store actions (approveMerchant, rejectMerchant, suspendMerchant)

- Redirect to merchant list on success

**Acceptance Criteria**:

- Success toasts show

## Dependencies

### External Dependencies

### Internal Dependencies

- `lib/admin/stores/merchants-store.ts` - Merchant store

- `app/(admin)/admin/merchants/page.tsx` - Merchants page

## Risks

1. **Form Validation Complexity**: User edit form may have complex validation. Mitigation: Keep validation simple, use Zod schemas.
2. **Merchant Actions Impact**: Approving/rejecting merchants may have side effects. Mitigation: Show clear warnings, require confirmation.
3. **Dialog State Management**: Managing multiple dialog states may be complex. Mitigation: Use separate state for each dialog, keep logic simple.
