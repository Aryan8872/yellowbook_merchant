# Plan 04-02: Test Complete Authentication Flow

## Objective
Test login, token refresh, and role-based redirects to ensure authentication works correctly with the enhanced middleware.

## Success Criteria
1. Admin user can log in and is redirected to `/admin/dashboard`
2. Merchant user can log in and is redirected to `/merchant/dashboard`
3. Token refresh works automatically without UI disruption
4. Role-based redirects work correctly for all roles
5. Logout clears tokens and redirects to login
6. Unauthorized access to protected routes redirects appropriately

## Tasks

### Task 1: Create Test Admin User
**Description**: Create a test admin user in the backend for authentication testing.

**Implementation Details**:
- Use backend admin panel or database
- Create user with role: ADMIN
- Set email and password for testing
- Verify user is active and verified
- Document test credentials (in secure location)

**Acceptance Criteria**:
- Test admin user is created
- User has ADMIN role
- User is active and verified

### Task 2: Create Test Merchant User
**Description**: Create a test merchant user for authentication testing.

**Implementation Details**:
- Use backend merchant panel or database
- Create user with role: MERCHANT_ADMIN
- Set email and password for testing
- Link user to a test merchant
- Verify user is active and verified
- Document test credentials (in secure location)

**Acceptance Criteria**:
- Test merchant user is created
- User has MERCHANT_ADMIN role
- User is linked to a merchant
- User is active and verified

### Task 3: Test Admin Login Flow
**Description**: Test admin login and verify redirect to admin dashboard.

**Implementation Details**:
- Navigate to `/login` or `/admin/auth/login`
- Enter admin credentials
- Click login button
- Verify JWT tokens are set in cookies (check DevTools Application tab)
- Verify redirect to `/admin/dashboard`
- Verify user role is ADMIN in auth store
- Verify admin dashboard loads correctly

**Acceptance Criteria**:
- Login succeeds with admin credentials
- Tokens are set in cookies
- Redirect to `/admin/dashboard` occurs
- Admin dashboard loads
- User role is ADMIN

### Task 4: Test Merchant Login Flow
**Description**: Test merchant login and verify redirect to merchant dashboard.

**Implementation Details**:
- Navigate to `/login` or `/merchant/auth/login`
- Enter merchant credentials
- Click login button
- Verify JWT tokens are set in cookies
- Verify redirect to `/merchant/dashboard`
- Verify user role is MERCHANT_ADMIN in auth store
- Verify merchant dashboard loads correctly

**Acceptance Criteria**:
- Login succeeds with merchant credentials
- Tokens are set in cookies
- Redirect to `/merchant/dashboard` occurs
- Merchant dashboard loads
- User role is MERCHANT_ADMIN

### Task 5: Test Token Refresh Flow
**Description**: Test automatic token refresh when access token expires.

**Implementation Details**:
- Log in as admin or merchant
- Wait for access token to expire (or manually expire in DevTools)
- Make an API request (navigate to a page that fetches data)
- Verify refresh token is used automatically
- Verify new access token is set in cookies
- Verify no UI disruption to user
- Verify API request succeeds with new token

**Acceptance Criteria**:
- Token refresh happens automatically
- New access token is set
- No UI disruption occurs
- API request succeeds

### Task 6: Test Role-Based Redirects
**Description**: Test that users are redirected based on their role.

**Implementation Details**:
- Log in as ADMIN
- Try to access `/merchant/dashboard` - should redirect to `/admin/dashboard`
- Log out
- Log in as MERCHANT_ADMIN
- Try to access `/admin/dashboard` - should redirect to `/merchant/dashboard`
- Log out
- Log in as USER (if available)
- Try to access `/admin/dashboard` - should redirect to `/` or login
- Try to access `/merchant/dashboard` - should redirect to `/` or login

**Acceptance Criteria**:
- ADMIN can access `/admin/*` but not `/merchant/*`
- MERCHANT_ADMIN can access `/merchant/*` but not `/admin/*`
- USER cannot access `/admin/*` or `/merchant/*`
- Redirects work correctly

### Task 7: Test Logout Flow
**Description**: Test logout and verify tokens are cleared.

**Implementation Details**:
- Log in as admin or merchant
- Click logout button
- Verify tokens are cleared from cookies
- Verify redirect to login page
- Try to access protected route - should redirect to login
- Verify auth store is cleared

**Acceptance Criteria**:
- Logout clears tokens
- Redirect to login occurs
- Protected routes redirect to login
- Auth store is cleared

### Task 8: Test Unauthorized Access
**Description**: Test that unauthenticated users cannot access protected routes.

**Implementation Details**:
- Log out (ensure no tokens)
- Try to access `/admin/dashboard` - should redirect to login
- Try to access `/merchant/dashboard` - should redirect to login
- Try to access `/admin/users` - should redirect to login
- Try to access `/merchant/branches` - should redirect to login
- Verify middleware redirects correctly

**Acceptance Criteria**:
- Unauthenticated access redirects to login
- Middleware protection works
- No protected content is accessible

### Task 9: Document Findings
**Description**: Document authentication test results.

**Implementation Details**:
- Create `04-02-AUTH-TESTS.md` in phase directory
- List all test scenarios
- Document pass/fail for each scenario
- Document any issues found
- Provide recommendations for fixes

**Acceptance Criteria**:
- Test results are documented
- Issues are documented
- Recommendations are provided

3. **Test User Creation Issues**: May not have permission to create test users. Mitigation: Use existing users or coordinate with backend team.
