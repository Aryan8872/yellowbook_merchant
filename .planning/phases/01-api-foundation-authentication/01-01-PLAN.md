<objective>
Build the standardized API client for the OfferNepal Merchant Portal conforming to the NestJS response envelope (`{ success, data, errorCode, meta }`), provide strict TypeScript DTOs, and implement a resilient transparent fallback mechanism that returns mock fixtures during development when endpoints fail or are unavailable.

Purpose: Provide a reliable communication layer so subsequent auth and feature development is decoupled from backend deployment status.
Output: `lib/api/types.ts`, `lib/api/client.ts`, and `lib/api/mocks/` fallback directory.
</objective>

<task type="auto">

  <files>lib/api/client.ts</files>
  <read_first>lib/api/types.ts, lib/api/mocks/index.ts</read_first>
  <action>
    Create `lib/api/client.ts`:
    - Define `apiClient` wrapping standard `fetch`:
      - Base URL configured from `process.env.NEXT_PUBLIC_API_URL || 'https://yellow-bookapi-production.up.railway.app'`.
      - Adds `Content-Type: application/json` and optional Bearer `Authorization` header.
      - Intercepts responses: if response is OK, parse JSON and return data.
      - Fallback mechanism: If fetch throws a network failure OR returns status 404/500/502/503:
        - Check `getMockResponse(endpoint, method)`.
        - If mock exists, log `console.warn('[API Fallback] Serving mock for ' + endpoint)` and return mock data wrapped in `{ success: true, data: mockData }`.
        - If no mock exists, throw `ApiError`.
  </action>

  <acceptance_criteria>
    - `lib/api/client.ts` exports `apiClient` with `get`, `post`, `put`, `delete` methods.

  </acceptance_criteria>
  <done>Resilient API client is operational and gracefully serves mock fixtures on network/server errors.</done>
