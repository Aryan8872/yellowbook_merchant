<objective>
Implement secure session management using Next.js Route Handlers with HttpOnly cookies, route protection middleware for all `/merchant/*` dashboard views, and an Auth Context provider supplying authenticated merchant state to the UI shell.

Purpose: Prevent client-side token exposure to XSS while enabling seamless server-side and client-side route authorization.
Output: Auth route handlers, Next.js `middleware.ts`, `lib/auth/auth-context.tsx`, and connected sidebar user controls.
</objective>

<task type="auto">
  <name>Task 1: Create Next.js Auth Route Handlers for HttpOnly Cookie Management</name>
  <files>app/api/auth/login/route.ts, app/api/auth/refresh/route.ts, app/api/auth/logout/route.ts, app/api/auth/me/route.ts</files>
  <read_first>lib/api/client.ts, lib/api/types.ts</read_first>
  <action>
    Create Route Handlers in `app/api/auth/`:
    - `login/route.ts`: Accepts `{ email, password }`, posts to `apiClient.post('/api/v1/auth/login')`, sets `accessToken` and `refreshToken` in `cookies()` with `httpOnly: true`, `secure: process.env.NODE_ENV === 'production'`, `sameSite: 'lax'`, `path: '/'`. Returns user profile in JSON.
    - `refresh/route.ts`: Reads `refreshToken` cookie, posts to `apiClient.post('/api/v1/auth/refresh', { refreshToken })`, rotates and sets new cookies, returns `{ success: true }`.
    - `logout/route.ts`: Calls backend logout endpoint, clears `accessToken` and `refreshToken` cookies (`maxAge: 0`), returns `{ success: true }`.
    - `me/route.ts`: Reads `accessToken` cookie, forwards call to backend `/api/v1/auth/me`, returns user profile. If token expired, tries refresh first.
  </action>
  <verify>npx tsc --noEmit</verify>
  <acceptance_criteria>
    - Next.js route handlers exist for login, refresh, logout, and me.
    - Cookies are written with `httpOnly: true` and cleared on logout.
  </acceptance_criteria>
  <done>Session route handlers securely mediate token persistence via HttpOnly cookies.</done>
</task>
